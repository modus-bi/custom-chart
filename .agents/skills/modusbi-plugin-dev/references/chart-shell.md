# Оболочка диаграммы

В исходном шаблоне CustomChart рисует голый контейнер. Кастомный плагин сам обеспечивает
оболочку, совместимую с CSS ядра. UI-части живут в ui/, данные/статус передаются props.

```text
div.hsChartContainer.hs<Имя>  id=container_<componentId>, фон config.bgColor
  div.componentHeader
    span
      div.titleText.strongly.nowrap
      div.subtitleText[.nowrap]
    span.path
  div.componentBody
    div.componentContainer  ref холста
    div.backSide
    предупреждение
    статус
```

`ref`/useChartSize относятся к componentContainer, а не ко всему корню с шапкой.
Контейнер холста сохраняется при смене статуса, React не рисует внутрь DOM, которым владеет
движок. Оверлеи внутри тела, не поверх всей шапки. Корневой фон покрывает и заголовок.

## CSS и размеры

Используй классы портала, `hsChartContainer` первым. `componentBody` получает
position:relative, flex:1 1 auto, min-height:0; холст — absolute с top/right/bottom/left:0,
если это нужно выбранной модели. Исходные CSS-чанки могут конфликтовать: проверяй computed
position/padding шапки, а не только наличие класса. При absolute-шапке резервируй её
фактическую высоту; при flex-шапке не вычитай высоту дважды. Кнопки справа должны оставаться
доступными. Исторические 38px/60px — наблюдения исходника, не универсальные размеры всех тем.
Проверяй разные темы, длинные заголовки, изменение плитки и body/canvas ненулевого размера.

## Текст и тема

- `showtitle === false` скрывает шапку; пустые title/subtitle также дают отсутствие шапки.
- Локализованное поле читается из `<key>__<locale>`, иначе базовое; null/undefined отсутствуют,
  пустая строка может быть заданным переводом. Локальный getLocal(source,key,locale)
  отличается от ядрового API с rawFlag; это должно быть понятно из сигнатуры/комментария.
- Подзаголовок из данных, если поддержан, имеет приоритет над локализованным config.subtitle.
  `nowrap` подзаголовка — при наличии заголовка; у заголовка присутствует всегда.
- Цвет заголовка — palette.secondaryTextColor, подзаголовка —
  palette.componentSubtitleTextColor ?? palette.disabledColor. Используй optional chaining.
  Поля hsTheme/locale/description добавляй в локальные типы, если их ещё не было.
- Идентификатор корня — container_<componentId>, только если id определён.

## Один статус

Единое решение на уровне ответа/props задаёт loading, needAxe, queryError, noData, badData,
ready. Учитывай fetching, error/errorMsg и обе ветки data/datas из [данных](data-query-contract.md).
Приоритет состояний, тексты и критерии непригодности выводи из задачи/существующего поведения;
**ноль сам по себе не ошибка** для любой диаграммы. Если решения нет, уточни.
Оверлей и lifecycle используют тот же статус. Вне ready освобождай инстанс, не DOM-контейнер.

## HTML и ошибки

Описание хранится как HTML. Перед dangerouslySetInnerHTML очищай его существующим надёжным
санитайзером или DOMPurify; не удаляй теги регуляркой. Очистка относится и к другим местам
вывода недоверенного HTML. Не называй устную договорённость исходного автора разрешением
пользователя на изменения вне текущей задачи.

backSide скрывается CSS ядра, показывается механизмом flipped. В описанном ядре оборот
скрыт в редакторе: проверять кнопку «Информация» нужно в отчёте.

Error boundary уровня плитки ограничивает сбой дочернего дерева; в React 16 это классовый
компонент. Не рассчитывай на неё для асинхронного callback, обработчика события или внешнего
движка: обрабатывай ошибки в точке вызова и переводи в состояние ошибки. Не утверждай,
что boundary никогда не ловит эффекты: охват commit/lifecycle зависит от React и вида вызова.
Проверь именно используемый путь, сохрани работоспособность соседних плиток.

## Проверка

jsdom: структура, условия шапки, локализация, id, статусы, очищенный HTML и error fallback.
Портал: computed CSS, кнопки, оборот, доступный размер, длинный текст, цвета темы, resize.
Unit-тест CSS-класса не подтверждает оформление в реальном портале.
