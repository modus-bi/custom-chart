# Цикл разработки через тесты

Это основной процесс разработки в репозитории. Если в окружении есть другой скилл про TDD общего назначения, здесь работает этот: он опирается на конкретных агентов проекта и его тестовую инфраструктуру.

Разработка идёт двумя агентами с непересекающимися правами. Тесты пишет один, код — другой, и ни один не может править чужие файлы. Это и есть весь механизм: разделение прав делает подгонку теста под код невозможной, а не просто нежелательной.

| Агент         | Фаза            | Правит                          | Не правит             |
| ------------- | --------------- | ------------------------------- | --------------------- |
| `test-writer` | RED             | `*.spec.{js,ts,tsx}`, `test/**` | продакшн-код          |
| `implementer` | GREEN, REFACTOR | `src/**` кроме спеков           | `*.spec.*`, `test/**` |

## Порядок

### 1. Определи требование

Одно требование за проход. Расплывчатая формулировка («сделай панель настроек удобнее») — не требование; уточни у пользователя, пока не сможешь описать проверяемое поведение.

Форма требования задана в CLAUDE.md, раздел «Требования не выдумываются»: вход, ожидаемое поведение, пустые данные, ошибка запроса, сохранённый прошлой версией конфиг. **Проход не начинается, пока хотя бы одно поле пусто** — недостающее спрашивается у пользователя, а не выбирается самостоятельно. Три последних поля обычно и оказываются пустыми, и именно они дают тесты, которые иначе никто не напишет.

### 2. RED — запусти `test-writer`

Передай в задаче: требуемое поведение, затронутые файлы, известные ограничения (форма `config`, контракт ядра, единицы измерения).

Получив отчёт, **проверь сам**, а не поверь на слово:

```bash
npx jest <путь к spec>
```

Убедись, что тест красный и падает на утверждении о поведении, а не на `Cannot find module` или забытой заглушке. Красный по неправильной причине — возврат агенту, а не повод идти дальше.

### 3. GREEN — запусти `implementer`

Передай пути к спекам и суть требования. Реализацию не диктуй — тесты уже её описывают.

Агент вернёт вопрос вместо кода, если сочтёт тест неверным. Это штатный исход: разбери противоречие, при необходимости отправь `test-writer` править тест, и только потом продолжай. Сам тест под код не подгоняй.

### 4. Проверь результат

```bash
npm test
npm run typecheck
npm run lint
```

Весь набор целиком — прогон занимает меньше секунды.

### 5. Ревью

- правки в `src/modules/CustomSettings/**` или `CustomReducers/**` → сабагент `settings-flow-reviewer`;
- правки контрактных экспортов, `CustomAxes` или `src/types/chartPlugin.d.ts` → сабагент `contract-reviewer`.

## Когда цикл неприменим

Прямо скажи об этом пользователю и предложи, чем заменить проверку, вместо того чтобы писать тест ради теста:

- **Отрисовка библиотекой визуализации.** Компонент, который владеет инстансом библиотеки и рисует императивно, тестируется не сравнением разметки, а на входе — на объекте опций, который до вызова библиотеки собирает чистая функция. Визуальную проверку даёт `npm start` поверх распакованного `prebuild/` и Playwright MCP.
- **Интеграция с ядром.** `loadDatas`, `drillDown`, `changeMultipleGlobalFilterValueAndApply`, `hsTheme` приходят от ядра. Мок проверяет вызов, но не то, что ядро ответит.

## Частые срывы

| Симптом                                   | Что делать                                                                               |
| ----------------------------------------- | ---------------------------------------------------------------------------------------- |
| Тест зелёный сразу после написания        | Не начинай реализацию. Либо поведение уже есть, либо тест не проверяет заявленное        |
| `implementer` предлагает поправить тест   | Не разрешай. Разбери противоречие и решай сам, чей файл менять                           |
| Тест падает на импорте                    | Красный по неправильной причине. Верни `test-writer`                                     |
| Хочется пропустить RED, «код же очевиден» | Тест, написанный после кода, проверяет то, что код делает, а не то, что он должен делать |
| Один проход покрывает три требования      | Разбей. Отладка провала в связке из трёх утверждений стоит дороже трёх проходов          |
