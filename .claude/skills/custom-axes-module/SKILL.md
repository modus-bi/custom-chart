# Модуль CustomAxes

## Суть

Модуль описывает панель полок редактора — ту часть интерфейса, куда пользователь перетаскивает
поля датасета. Это единственный модуль плагина, где **отсутствие кода не означает поведение по
умолчанию**.

Все методы контракта необязательны. Но метод, которого нет, возвращает `undefined`, а ядро
трактует это буквально: полка без имени, пустая панель, скрытая пилюля. Ошибок в консоли нет,
падений нет — редактор просто выглядит сломанным, и причина не видна ниоткуда.

Отсюда главное правило: **реализовывать все методы, кроме одного осознанного исключения**.

## Устройство

```
src/modules/CustomAxes/
  index.tsx        объект CustomAxes целиком
  index.spec.ts    спек рядом
```

Модуль остаётся одним файлом, пока методы — короткие выражения. Дробить его на файл-на-метод
не нужно: одиннадцать однострочников читаются лучше одиннадцати файлов. Разросся конкретный
метод — выносится **его** тело чистой функцией в `../CustomChart/lib/`, а в объекте остаётся
вызов.

Файл `.tsx`, а не `.ts`: два метода возвращают JSX.

## Единственное осознанное исключение

`getPillTypeOptions` — единственный метод, чьё отсутствие штатно означает «использовать
список типов пилюль ядра». Его не реализуют, пока плагину не нужно этот список **сузить**.

Все остальные десять реализуются всегда, даже если тело тривиально: `isVisibleAxe` возвращает
`true`, `isVisibleField` — `true`. Тривиальная реализация — это документ: она говорит
следующему, что поведение выбрано, а не забыто.

**Реализовав его — сверяй `axisType`, а не `axisName`.** Комментарий контракта описывает
`axisName` как тип полки, но фактически ядро кладёт туда **отображаемое имя** полки, которое
пользователь может переименовать («Значения» → «Показатель»), а тип едет отдельным полем
`axisType`. Снято на живом портале: сверка по `axisName === 'values'` возвращала пустой
массив всегда — то есть прятала пункт «Тип» у всех полок разом. Пустой массив, к слову, — это
и есть штатный способ спрятать пункт «Тип» у полки, которой он не нужен.

## Правила по методам

### Имена и иконки

`getAxeName` берёт имя из конфига и карты ядра — `axe.title || axisNames[axe.type]`, — а не из
своих строковых литералов. Оба слагаемых обязательны: `title` пользователь может переименовать
прямо в панели, а карта приходит на языке интерфейса, тогда как литерал в коде — всегда на
одном.

`renderAxeIcon` рисует иконку компонентом шрифтовой иконки ядра, который приходит в контексте
(`HsMuiFontIcon`): плагин выбирает класс и подпись, а не вёрстку. Классы стоит повторять за
штатной панелью полок — `fa fa-bars` у «Значений», та же иконка с `rotate(90deg)` у
«Категорий», `fa fa-filter` у «Фильтров».

Подпись иконки берётся **тем же правилом, что и `getAxeName`** (`axe.title || axisNames[type]`),
иначе переименованная полка окажется подписана в двух местах по-разному.

Для полки, которой нет в своей карте иконок, метод возвращает **`null`, а не `undefined`**.
Разница существенна: `null` — это «иконки нет», `undefined` — «метод ничего не вернул», и ядро
в dev-сборке пишет об этом предупреждение.

### Видимость и запреты

`isVisibleAxe` — метод осей, которому ядро **не передаёт `componentType`**. Опираться в нём на
тип компонента нельзя, только на саму полку и конфиг.

Второй такой метод — `getPillTypeOptions` (`PillTypeOptionsContext` в контракте: `config`,
`field`, `axisName`, `axisType`, `fieldIndex`, и никакого `componentType`). Тип компонента ядро
передаёт первым аргументом диспетчера, но в объект пропсов не кладёт — обращение к нему внутри
метода даст `undefined`. Остальные девять получают `componentType` через `AxeContextBase`.

`isDisabledAxe` **помечает пилюлю неактивной**: ответ `true` ядро красит фоном `#A1A1A1`
(сборка пилюли в `prebuild/report.*.js`). Метод получает `fieldIndex` — порядковый номер пилюли
на полке, — и это единственный способ сказать пользователю, что лишняя пилюля лежит в конфиге,
но на запрос не влияет. Полем это метод не запрещает: положить на полку можно всё, что
пропускает `isVisibleField` и сама полка.

**Решение выводится из ёмкости полки, а не из списка полок.** Ёмкость объявлена полем
`selectedFieldIndex` самой полки (`ChartAxe` в `model/plugin.types.ts`) — то же поле читает
ядро в своей реализации метода и правят его штатные тумблеры:

| `selectedFieldIndex` | Что означает               | Какие пилюли серые       |
| -------------------- | -------------------------- | ------------------------ |
| `-2`                 | полка принимает несколько  | ни одной                 |
| `-1`                 | полка отключена            | все                      |
| `>= 0`               | работает ровно одна пилюля | все, кроме этого индекса |

Полка без объявленной ёмкости считается полкой на одну пилюлю: так её нормализует
`CommonConfigEditor.setAggregationAuto` (`undefined` → `0`).

`>= 0` — это **индекс** действующей пилюли, а не всегда нулевой: сравнивать нужно с ним, а не
с нулём. Так же читает его `CommonDataAdaptor` (`selectedFieldIndex >= 0 ? selectedFieldIndex : 0`).

Ёмкость меняется в рантайме — тумблер «Все/Первое» полки «Значения» переключает её `-2 ↔ 0`,
тумблер полки «Категории» — `-1 ↔ 0` (редьюсеры ядра в `prebuild/app.*.js`). Поэтому правило
читает конфиг на каждый вызов, а не фиксируется таблицей полок в коде плагина.

`isVisibleField` прячет отдельную пилюлю на полке. Прятать пилюлю, которая влияет на запрос, —
плохая идея: пользователь видит результат, но не видит причины.

### Меню и элементы пилюли

`isVisibleAxeDragItemMenuOption` вызывается ядром **порядка 28 раз за один рендер меню** — по
разу на пункт. Тело обязано оставаться дешёвым: `switch` по `optionName` либо таблица
«полка → пункты» и поиск строки в коротком массиве. Создавать объекты, замыкания и копии
конфига внутри — недопустимо.

**Полки в контексте нет.** Ядро кладёт в пропсы этого метода только `config`, `field` и
`componentType` (снято по сборке меню пилюли в `prebuild/report.*.js`). Значит полка, если она
нужна для решения, ищется по `id` поля обходом `config.axes` — ровно так же поступает штатная
реализация ядра для плагинных типов. Полок пять, полей на них единицы: обход дешевле, чем
кажется, и другого способа узнать полку у метода нет.

Для плагинного типа ядро **не проверяет собственное условие видимости**: обёртка
`isVisibleDragItemMenuOption` сразу спрашивает плагин и берёт его ответ. Значит перечень обязан
быть полным — не названный пункт исчезает, а лишний появляется там, где ядро само бы его не
показало.

То же и с `isVisibleAxeDragItemElement`, только вызовов меньше.

Оба метода пишутся со **всеми** значениями, которые присылает ядро, — включая те, что
возвращают `false`. Перечисленный явно набор служит списком доступных возможностей: без него
никто не узнает, что пункт существует, кроме как прочитав ядро. Если набор оформлен таблицей,
а не `switch`-ем, перечень имён `renderXxx` с русскими подписями кладётся комментарием над ней.

Часть подписей — не пункты, а содержимое одного блока: «Тип фильтра», «Автофильтр»,
«Зависит от», «Сброс», «Значение при сбросе», «Невидимый» и «Локальный» приходят вместе с
`renderFilterSettings` и по отдельности не управляются. Порядок пунктов в меню тоже задаёт
ядро, а не порядок таблицы плагина.

### Переключатели

`renderAxeToggle` не создаёт свои переключатели — штатные приходят готовыми в контексте
(`valuesToggle`, `seriesToggle`). Метод только решает, на какой полке какой показать.

### Порядок полок

`sortAxes` возвращает полки в порядке отображения. **Пустой массив означает пустую панель** —
это ровно та ошибка, из-за которой панель выглядит сломанной; заполняется из `config.axes`.

## Тесты

Все методы — чистые функции от контекста, тестируются целиком без DOM и без портала.
Проверять стоит:

- `sortAxes` возвращает непустой набор и в ожидаемом порядке;
- `getAxeName` даёт непустое имя для каждого типа полки из `defaultConfig.json` и следует за
  переименованием полки (`axe.title`);
- `isDisabledAxe` красит серыми ровно лишние пилюли — по каждому значению `selectedFieldIndex`
  отдельно: `-2` (серых нет), `-1` (серые все), `0` и ненулевой индекс действующей пилюли;
  плюс полка без объявленной ёмкости;
- `renderAxeIcon` отдаёт иконку для каждой полки конфига и `null` для полки вне набора,
  а подпись иконки следует за переименованием полки;
- `getPillTypeOptions`, если он реализован, сверяется по `axisType` — в том числе когда полку
  переименовали;
- `isVisibleAxeDragItemMenuOption` возвращает `true` ровно для тех пунктов, которые плагин
  показывает, — по каждой полке отдельно, включая вычисляемое поле и поле вне полок;
- набор ключей объекта совпадает с ожидаемым списком методов — тест ловит метод, потерянный
  при рефакторинге.

Последняя проверка стоит одной строки и закрывает главный риск модуля: молча исчезнувший метод.

## Частые ошибки

| Ошибка                                             | Что видит пользователь                                 |
| -------------------------------------------------- | ------------------------------------------------------ |
| Метод не реализован «за ненадобностью»             | полка без имени, пустая панель, пропавшая пилюля       |
| `sortAxes` возвращает `[]`                         | панель полок пуста                                     |
| `renderAxeIcon` возвращает `undefined`             | предупреждение ядра в консоли dev-сборки               |
| `isDisabledAxe` всегда `false`                     | лишняя пилюля выглядит рабочей, но в запрос не идёт    |
| Окраска по списку полок вместо ёмкости             | тумблер полки меняет ёмкость, а цвет пилюль — нет      |
| Сравнение `fieldIndex` с нулём вместо ёмкости      | при ёмкости `>= 1` серой становится действующая пилюля |
| Имя полки строковым литералом                      | русский текст в интерфейсе на другом языке             |
| Имя полки без `axe.title`                          | переименованная полка возвращает прежнее имя           |
| Тяжёлое тело `isVisibleAxeDragItemMenuOption`      | меню пилюли заметно тормозит: 28 вызовов на рендер     |
| Опора на `axe`/`axisType` в меню пилюли            | `undefined`: в контексте только `config` и `field`     |
| Опора на `componentType` в `isVisibleAxe`          | `undefined`: ядро не передаёт его в этот метод         |
| Опора на `componentType` в `getPillTypeOptions`    | `undefined`: второй метод без него в контексте         |
| `getPillTypeOptions` сверяется по `axisName`       | пункт «Тип» пропал у всех полок: там имя, а не тип     |
| `getPillTypeOptions` реализован «на всякий случай» | список типов пилюль сузился там, где этого не хотели   |
| Своя вёрстка переключателей вместо `valuesToggle`  | элементы не совпадают со штатными по виду и поведению  |

## Смежные скиллы

- `sync-contract` — сверка сигнатур методов с контрактом ядра после его обновления;
- `custom-chart-module` — куда выносить тело метода, если оно разрослось;
- сабагент `contract-reviewer` — запускать после правок этого модуля.
