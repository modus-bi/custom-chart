# Сборка и проверка дистрибутива

Архив ModusBI — `<manifest.name>.tar.gz` с двумя файлами в корне: plugin.js и manifest.json.
Это **не** пакет скилла Codex. Установка на портал и выбор версии/идентификатора — отдельные
решения в рамках задачи пользователя, не побочный эффект команды сборки.

## Порядок

1. Прочитай scripts и create-plugin.js целевого проекта. Выполни typecheck/lint/tests;
   исправь относящиеся к работе ошибки перед подготовкой релизного артефакта.
2. Собери production `npm run build`. Затем положи проверенный манифест в build/manifest.json:
   такой порядок безопасен и при output.clean. Не перезаписывай существующий манифест примером.
   Образец есть в [assets](../assets/manifest.example.json), приоритет у целевого проекта.
3. Используй уже выбранные name/version/description/apiVersion. Если решения нет — уточни.
   apiVersion манифеста не равно contractVersion/coreVersion по определению; не подставляй
   одно вместо другого. package.json и manifest.version не должны расходиться без причины.
4. Проверь, что temp/ сборщика не содержит пользовательских файлов: исходный create-plugin.js
   удаляет его рекурсивно после успеха. Если занят чужими данными — не запускай такой сборщик
   до выбора отдельной временной папки/исправления. Не очищай каталог вслепую.
5. `npm run build:plugin`, затем проверь архив независимо от exit code. Исходный скрипт
   перехватывает ошибки и может завершиться с кодом 0 без нового архива.

Механика слота:

```text
CustomChart0 (webpack UMD)
  → CustomChartNNN (create-plugin.js, только первые 1000 символов)
  → CustomChartN (сервер портала, ReplacementInTheBody)
```

Не переименовывай технические CustomChart0/CustomChartNNN под название диаграммы.
В манифесте path=plugin.js, type=ReplacementInTheBody, template=CustomChartNNN,
replacement=%ClassName%. Имя архива должно совпадать с name и быть безопасным именем файла,
а не путём с ../ или разделителями.

## Независимая проверка

Read-only помощник требует Node >=22 и установленный в **проекте** пакет tar (есть в шаблоне):

```text
node <каталог-скилла>/scripts/verify-package.mjs <корень-плагина> <путь-к-архиву>
```

Относительный путь к архиву отсчитывается от корня плагина, не от каталога скилла.
Код 0 означает: корректный gzip/tar, ровно два обычных файла без путей/ссылок/дубликатов,
валидный манифест и правило подстановки, совпадающая версия, содержимое plugin.js соответствует
**нынешнему** build/custom_chart_0.js после ожидаемой замены, манифест совпадает с нынешним
build/manifest.json. Проверка по содержимому не выдаёт старый архив за новый после неудачной
сборки. Код 1 — ошибка. Скрипт ничего не распаковывает и не устанавливает.

Дополнительно проверь webpack stats: react/react-dom внешние, React runtime не включён
внутренним модулем. Один поиск слова React или размер бандла это не доказывает. Свой ECharts
закономерно увеличивает размер. production bundle не должен включать dev source map/runtime.

Проверка архива не доказывает подстановку на сервере или работу ядра: они проверяются на
тестовом портале после разрешённой установки. `CustomChart0` в произвольной строке кода может
иметь иной смысл; помощник консервативно отклоняет остаток и требует анализа, не удаляй все
совпадения в исходниках без разбора. Для изменённого формата сборщика адаптируй проверку явно.

Отчёт: путь/размер/SHA-256, версия и состав архива, локальные проверки, отдельный статус
портальной установки. Не публикуй, не коммить build/архивы и не меняй версию автоматически.
