# Редьюсер настроек

`src/modules/CustomReducers/changeCustomChartReducer.ts` получает `(state, action, options)`;
сигнатура — из контракта. Он записывает готовое значение в копию configDraft и передаёт
новое состояние ядру. Спек — рядом. Полный UI-путь описан в [настройках](new-setting.md).

## Инварианты

- Простые присваивания: таблица `COMMANDS: команда → путь`, вложенность через точки.
  Неизвестная команда возвращает тот же state, без callback и без исключения.
- Признавай только собственные ключи таблицы, например `Object.prototype.hasOwnProperty.call`:
  команда `toString` не должна считаться записью из Object.prototype. Пути задаёт доверенная
  таблица, не произвольная строка из action; не разрешай prototype-ключи при обобщении setter.
- `structuredClone` применяется к данным черновика, а state/component копируются spread.
  Не клонируй целое состояние с callback/React-элементами и не мутируй входной configDraft.
- Setter создаёт недостающие промежуточные объекты старого отчёта. Поведение при отсутствии
  **самого** configDraft сверь с текущим ядром/состоянием, не подменяй его выдуманной структурой.
- Для изменённого состояния обязателен `return options.autoApplySettings(nextState)`.
  Это функция, не флаг. Не возвращай nextState после вызова, игнорируя результат callback.
- В описанном ядре callback мутирует переданный черновик (dirty/unsaved), а при auto-apply
  обновляет config через prepareAxes. Поэтому независимость клона требуется до вызова.
  Ручной режим также обслуживает ядро: самостоятельное копирование draft в config его обходит.
- Преобразование/валидация значения — у контрола панели. Запросы, таймеры, адаптер и логирование
  не относятся к редьюсеру. Для составного атомарного действия выбери отдельную явную ветку
  по задаче: две отдельные команды не всегда сохраняют атомарность и могут примениться дважды.

## Минимальная проверка поведения

1. Известная команда записывает правильное поле и сохраняет соседние поля.
2. Неизвестная команда, включая имя свойства прототипа, возвращает исходную ссылку.
3. Входной configDraft/вложенные ветки не изменены даже при мутирующем autoApplySettings.
4. Отсутствующая вложенная ветка создаётся; 0/false/null записываются как согласовано.
5. autoApplySettings вызван ровно один раз с новым состоянием, и его результат возвращён.
   Одного `jest.fn(s => s)` недостаточно для проверки возврата — используй отличимый результат.

В исходном шаблоне редьюсер — документированная заглушка. При добавлении COMMANDS меняются
ожидания теста для новой команды, но не для неизвестной. Исправление делает агент в фазе RED,
а не скрытым ослаблением проверки во время GREEN.
