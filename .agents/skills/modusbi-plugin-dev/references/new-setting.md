# Настройка панели: полный путь

Перед изменением установи из задачи/проекта название, секцию, поле, единицы, диапазон и дефолт.
Уточни только отсутствующие решения. При удалении/переименовании учти сохранённые отчёты,
старые команды и миграцию поля; не оставляй случайно читаемую старую ветку.

## Пять мест и совместимость

| Точка | Файл / действие |
| --- | --- |
| Контрол в секции | `CustomSettings/sections/<Имя>Section.tsx`, `changeChart(command, { value })` |
| Подключение | `CustomSettings/Settings.tsx` |
| Команда → путь | COMMANDS в `CustomReducers/changeCustomChartReducer.ts` |
| Тип | ChartConfig в `CustomChart/model/plugin.types.ts` |
| Дефолт | `CustomChart/model/defaultConfig.json` для читаемых UI/отрисовкой настроек |

Для **готовых секций ядра** `pluginImports.sections` нет собственной команды: они обновляют
configDraft своими callback. Не добавляй им фиктивные записи COMMANDS. Это касается
DataOptionsContent, precisionSliderContent, suffixSelectContent и других штатных секций.
Объяви реально используемые поля в типе; отсутствие дефолта может быть намеренным режимом
ядра (например необязательный bigNumberClasses), не заполняй его произвольно.

С первой собственной секцией создаются общие `CustomSettings/types.ts` (ChangeChart,
SettingsSectionProps) и `sectionConfig.ts` (`getSectionConfig`). Последний выбирает
`component.configDraft ?? component.config ?? {}`. Секция читает черновик, иначе применённый
конфиг, иначе пустой объект. Не копируй это выражение в каждую секцию.

Новое корневое поле старого отчёта читай через общий `model/configFields.ts`:
`readConfigField` и список OptionalConfigField. Дефолт один — из defaultConfig.json.
Обычно нужен `??`, сохраняющий 0/false; если null — самостоятельное допустимое значение,
отличай его от undefined и не заменяй дефолтом. Вложенные ветки читай через optional chaining
и тот же источник дефолтов. Старый отчёт не обязан физически содержать новую ветку.

## Контролы ядра

UI приходит пропом `pluginImports.components`, в секцию — суженным `components`.
Секция имеет displayName и русские подписи. Пункт обычно остаётся JSX в секции;
отдельный компонент нужен для состояния/логики или общего повторяемого контрола.

| Значение | Контракт |
| --- | --- |
| Булево | SettingsItem type='inline' с title; SettingsToggle **toggled/onToggle**, без дублирующего label |
| Цвет | SettingsColorPicker color/float='right'; сброс callback нормализуется в null |
| Точное число | Общий NumberSettingItem: SettingsItem inline + SettingsTextField numeric, min/max/step |
| Один вариант | Общий SelectSettingItem на SettingsMultiselect: multiple=false, clearable=false, title='' |
| Набор вариантов | Группа SettingsCheckbox по элементам |

```tsx
<SettingsItem type='inline' title='Показывать легенду'>
  <SettingsToggle
    toggled={Boolean(legend.visible)}
    onToggle={(_event: unknown, checked: boolean) =>
      changeChart('TOGGLE_LEGEND', { value: checked })}
  />
</SettingsItem>
```

`legend` в примере уже прочитан с правильным дефолтом. Props тумблера подтверждены исходной
документацией по ядру; проверяй ту же форму в моках. `onToggle` передаёт значение вторым
аргументом. У цвета callback `value ?? null`, чтобы сброс сохранился в JSON.

Для numeric SettingsTextField исходное ядро вызывает `onChange(event, value)` через 500 мс,
число уже преобразовано. Обёртка проверяет конечность/диапазон и промежуточный ввод, не
дублирует debounce. Приведение делай **на стороне панели**, редьюсер записывает готовое значение.
CSS-класс `NumberSettingItem__input` использует ширину портала; не вводи собственные стили
без необходимости. Слайдер подходит визуальному выбору (например прозрачность), но не
точному размеру шрифта/отступа. Для предопределённых шаблонов подписи используй список;
свободный язык шаблонов реализуй только по отдельному требованию, не запрещай выбор пользователя.

## Ревью цепочки после изменения

1. Секция подключена; читает то же поле, которое команда записывает. Общие типы/хелперы
   созданы тогда, когда используются; отсутствие неиспользуемого NumberSettingItem — не дефект.
2. Сопоставь все команды UI и COMMANDS, включая команды из props. Найди отсутствующие и
   мёртвые команды; готовые секции ядра из этого сопоставления исключи.
3. Тип/дефолт/чтение старого конфига согласованы; сохраняются false/0/null по смыслу поля.
4. Для известной команды копируется configDraft, возвращается результат autoApplySettings.
   Неизвестная команда возвращает исходное состояние без вызова autoApplySettings.
5. Тест провоцирует мутацию со стороны autoApplySettings и подтверждает независимость входа;
   отдельным возвращаемым объектом проверяет, что редьюсер возвращает именно результат callback.
6. Мок UI повторяет фактические callbacks ядра; RED для первой настройки обновляет тест заглушки.
7. Проверь typecheck, lint, спеки, затем автоматическое/ручное применение и сохранение на портале.

Если панель по задаче всё ещё заглушка, не объявляй отсутствие секций ошибкой. При read-only
ревью выдавай реальные находки: файл/строка, сценарий отказа, исправление. Не исправляй
попутно все соседние секции только из-за несовпадения с примером.
