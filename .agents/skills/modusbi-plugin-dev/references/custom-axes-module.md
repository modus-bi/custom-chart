# CustomAxes: полки и пилюли

Источник сигнатур — целевой `CustomAxesModule`. В исходном контракте 11 необязательных методов,
шаблон реализует 10. Необязательность типа не означает полезного поведения редактора:
отсутствие метода обычно даёт `undefined` и пустую/скрытую часть панели.

Единственное штатное исключение — отсутствие `getPillTypeOptions`: ядро использует свой список.
Реализуй его, когда плагину нужен собственный ограниченный список. Не добавляй пустую заглушку
ради числа методов. Реализованные методы должны возвращать определённый результат; для
отсутствующей иконки — `null`. В dev-ядре возможны предупреждения о `undefined`.

Модуль обычно остаётся `src/modules/CustomAxes/index.tsx` со спеком рядом: JSX нужен иконкам
и переключателям. Не дроби короткие методы на отдельные файлы.

## Семантика

| Метод / свойство | Правило |
| --- | --- |
| getAxeName | `axe.title || axisNames[axe.type]`: сохраняй переименование и язык ядра |
| renderAxeIcon | Используй HsMuiFontIcon из контекста; подпись по тому же правилу; неизвестный тип → null |
| sortAxes | Полки в требуемом порядке из config.axes; [] означает пустую панель |
| isVisibleAxe | Не получает componentType; опирайся на доступный config/axe |
| getPillTypeOptions | Также без componentType; сравнивай axisType, поскольку axisName — отображаемое имя |
| isDisabledAxe | Отмечает пилюлю неактивной; **не валидирует возможность бросить поле** |
| isVisibleField | Управляет видимостью пилюли; не скрывай используемое в запросе поле случайно |
| renderAxeToggle | Используй переданные valuesToggle/seriesToggle, а не повторяй UI ядра |

`selectedFieldIndex` определяет активность: `-2` — все пилюли, `-1` — ни одной,
`>=0` — ровно указанный индекс (не всегда нулевой). Отсутствующее значение в описанном ядре
нормализуется к `0`. Тумблеры изменяют ёмкость в runtime; читай актуальный конфиг.
Та же активность должна учитываться при сборке запроса.

## Меню пилюли

`isVisibleAxeDragItemMenuOption` вызывается многократно (в описанной сборке около 28 раз
на меню). Ответ должен быть дешёвым; не клонируй конфиг и не обходи данные диаграммы.
В контексте исходного ядра есть config/field/componentType, но нет самой полки: ищи её
по id поля среди config.axes при необходимости. Проверь это на целевой версии.

Для плагинного типа ядро использует ответ плагина непосредственно, не дополняя своим
списком видимости. Явно учти доступные optionName/имена renderXxx, включая запрещённые,
и поясни значения. `renderFilterSettings` включает несколько контролов фильтра сразу,
их видимость нельзя разложить на несуществующие отдельные опции. Порядком управляет ядро.
Сходные правила относятся к `isVisibleAxeDragItemElement`.

## Проверки и ревью

- Набор экспортированных методов соответствует целевому контракту и принятому исключению.
- Каждый реализованный метод возвращает значение; пустые заглушки помечены как заглушки,
  а в готовом плагине проверены на соответствие ожидаемой панели.
- Порядок полок, локализация/переименование имени и иконки.
- Ёмкости `-2`, `-1`, `0`, ненулевой индекс и отсутствующая ёмкость.
- Типы пилюль работают после переименования полки; нет обращения к отсутствующему componentType.
- Видимость меню по каждой полке, вычисляемое поле и поле вне полок.
- Допустимость drop проверяется по реальному ConfigEditor/механизму ядра, а не по серому цвету.

Методы иконок можно проверять как React-элементы; основную чистую логику — без DOM.
После контрактной правки выполни [сверку контракта](sync-contract.md).
