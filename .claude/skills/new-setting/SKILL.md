# Новая настройка панели редактора

Настройка живёт в трёх-четырёх местах сразу. Пропуск любого — тихий отказ: ни ошибки компиляции, ни предупреждения в консоли, настройка просто не работает.

## Точки

| #   | Что                                                                                  | Где                                                      |
| --- | ------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| 1   | Контрол внутри секции, зовёт `changeChart(command, { value })` — ровно два аргумента | `src/modules/CustomSettings/sections/<Секция>.tsx`       |
| 2   | Секция подключена в панели                                                           | `src/modules/CustomSettings/Settings.tsx`                |
| 3   | Запись `command → путь в конфиге` в таблице команд                                   | `src/modules/CustomReducers/changeCustomChartReducer.ts` |
| 4   | Поле дефолта (если настройка читается при рендере)                                   | `src/modules/CustomChart/defaultConfig.json`             |

**Отдельного компонента на каждый пункт в этом плагине нет.** Пункт — это UI-примитив ядра (`SettingsItem` и контрол внутри) прямо в теле секции; каталогов вида `<Что><Контрол>SettingItem/` быть не должно. Компонент заводится, только когда пункт несёт собственное состояние или заметную логику.

Секции — файлы в `src/modules/CustomSettings/sections/`. Сейчас в шаблоне их нет ни одной — `Settings.tsx` рендерит `null`. Первая секция заводится с нуля по описанному ниже шаблону и подключается в `Settings.tsx`; вместе с ней заводится `src/modules/CustomSettings/types.ts` с общими типами панели (`ChangeChart` и тип props секции) — до первой секции файла нет, копировать типы не с кого.

## Порядок работы

1. **Уточни у пользователя**, чего не хватает в формулировке: имя настройки в интерфейсе (русский литерал прямо в JSX), секция (новая или существующая), тип контрола, поле в `config`, значение по умолчанию.
2. **Посмотри соседа.** Если секция и похожий пункт уже есть — ближайший по типу контрола пункт в той же секции служит шаблоном. Если это первая настройка шаблона, соседа ещё нет — работай от примера ниже.
3. **Реализуй через цикл `/tdd`**: `test-writer` пишет красный тест на `changeCustomChartReducer` и, если меняется или заводится секция, на неё саму; `implementer` доводит до зелёного. Редьюсер — чистая функция, тестируется без окружения; секция — с docblock'ом `/** @jest-environment jsdom */` и заглушками UI-примитивов ядра.
4. Прогони `npm run lint`. Типы уже проверил PostToolUse-хук.
5. Отдай на проверку сабагенту `settings-flow-reviewer` — он сверяет замыкание команд и вызов `autoApplySettings`.

## Шаблон пункта секции

UI-примитивы **не импортируются** — приходят из ядра через `pluginImports.components` в `Settings.tsx`, а секции получают уже сужённый набор пропом. Значение читается из `component.configDraft` (с фолбэком на `component.config`), обработчик зовёт `changeChart` напрямую. Условный пример — тумблер «Показывать легенду», пишущий поле `legend.visible`:

```tsx
<SettingsItem title='Показывать легенду'>
  <SettingsToggle
    checked={Boolean(config.legend?.visible)}
    onChange={(value: boolean) => changeChart('TOGGLE_LEGEND', { value })}
  />
</SettingsItem>
```

Секция целиком получает объект props вида `{ component, changeChart, components }` — для первой секции соответствующий тип заводится в `src/modules/CustomSettings/types.ts` (форма — в TS-конвенциях, скилл `typescript-coding-standards`), для последующих — импортируется оттуда, а не копируется в файл. У каждой секции есть `displayName`.

Читай значение так, чтобы `false` и `0` оставались валидными настройками — не заменяй `Boolean(config.legend?.visible)` на `config.legend?.visible || true`: `||` подменит `false` дефолтом.

## Шаблон записи в редьюсере

`changeCustomChartReducer.ts` сейчас — заглушка (`(state, action, options) => state`), с рабочей версией в комментарии файла. Заводя первую настройку, замени тело на таблицу соответствия `COMMANDS` — веток `if (action.command === ...)` в редьюсере быть не должно:

```ts
/**
 * Таблица «команда → путь в конфиге». Веток `if` на команды в этом файле быть не должно:
 * новая настройка добавляется строкой сюда и пунктом в секции панели настроек.
 *
 * Вложенные поля конфига пишутся через точку: `'outline.width'`.
 */
export const COMMANDS: Record<string, string> = {
  TOGGLE_LEGEND: 'legend.visible',
  // сюда — новая настройка
};

/** Пишет значение по пути с точками, создавая недостающие объекты. */
const setByPath = (target: Record<string, unknown>, path: string, value: unknown): void => {
  const keys = path.split('.');
  const last = keys.pop() as string;
  const parent = keys.reduce<Record<string, unknown>>((node, key) => {
    if (typeof node[key] !== 'object' || node[key] === null) node[key] = {};
    return node[key] as Record<string, unknown>;
  }, target);
  parent[last] = value;
};

export default function changeCustomChartReducer(
  state: PluginState,
  action: PluginAction,
  options: CustomReducersOptions,
): PluginState {
  const path = COMMANDS[action?.command];
  if (!path) return state;

  const configDraft = structuredClone(state.component.configDraft);
  setByPath(configDraft, path, action?.settings?.value);

  const nextState = {
    ...state,
    component: { ...state.component, configDraft },
  };

  return options.autoApplySettings(nextState);
}
```

Редьюсер клонирует конфиг (`structuredClone`) и пишет по пути, создавая недостающие подобъекты, — поэтому подобъект, которого нет в старом отчёте, руками создавать не нужно. Дефолт всё равно добавь в `defaultConfig.json`: его читает секция при рендере.

Рантайм-зависимостей у шаблона нет вовсе. Если предпочитаешь `lodash.set` вместо `setByPath`, пакет придётся добавить — и он попадёт в бандл.

Новую настройку нужно объявить в `ChartConfig` (`src/modules/CustomChart/plugin.types.ts`) — отдельного типа черновика в проекте нет, `configDraft` типизируется тем же интерфейсом.

Если значение настройки нуждается в приведении типа (например строка из текстового поля должна лечь в конфиг числом или `null`) — таблица `COMMANDS` кладёт значение как есть, приведение нужно добавить в редьюсер до записи по пути или обсудить с пользователем отдельный путь для таких команд.

## Обязательное: autoApplySettings

Возврат редьюсера обязан быть обёрнут в `options.autoApplySettings(state)`. Это **функция ядра, а не флаг**: без неё правка осядет в `configDraft` и не доедет до компонента. Она же учитывает режим ручного применения, помечая черновик как dirty.

Заводя первую настройку — добавь обёртку сам (см. пример выше) и не добавляй путей выхода в обход неё.

## Частые ошибки

| Симптом                                             | Причина                                                                                             |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Настройка меняется в панели, диаграмма не реагирует | Команды нет в таблице `COMMANDS`, либо имя разъехалось между вызовом `changeChart` и ключом таблицы |
| Правка применяется, но откатывается                 | Обход `autoApplySettings`                                                                           |
| Переключатель не выключается                        | Значение читается через `\|\|` вместо явной проверки — `false` подменяется дефолтом                 |
| Секция показывает `undefined`                       | Секция читает один путь, таблица пишет другой                                                       |
| `tsc` ругается на неизвестное поле                  | Поле не объявлено в `ChartConfig`                                                                   |
