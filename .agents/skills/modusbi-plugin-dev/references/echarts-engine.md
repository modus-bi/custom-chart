# ECharts

Читай после [lifecycle](chart-lifecycle.md), только если ECharts выбран задачей/проектом.
Версию и доступность определяй по целевому package lock и порталу, не по историческому числу.

## Два способа подключения

1. Собственная модульная версия: imports из `echarts/core`, `echarts/charts`,
   `echarts/components`, `echarts/renderers`; `echarts.use([...])` регистрирует нужные части
   один раз на уровне engine-модуля. `echarts` и эти подпути не должны externalize-иться.
   Это предпочтение исходного шаблона, если проект ещё не выбрал иначе.
2. Версия портала: сначала проверь наличие/версию глобальной библиотеки и нужного API,
   затем external `echarts: 'echarts'` и импорт соответствующий этой записи. Не смешивай
   его с модульными подпутями, которые webpack мог бы собрать локально. Для компиляции нужны
   совместимые объявления типов. При отсутствии глобали показывай диагностируемый отказ.

Собственная библиотека и глобальная версия портала могут сосуществовать изолированно.
Опасно использовать разные копии для одного инстанса, регистрации или поиска по DOM.
Не объявляй любой бандл большого размера ошибочным: локальная библиотека закономерно его увеличит.

## Адаптер и типы

engine/engine.ts импортирует библиотеку и реализует create/render/resize/destroy.
engine/engine.types.ts содержит type-only ChartSpec/EChartsType и интерфейс моста;
ChartSize переиспользует существующий тип. model/buildSpec может импортировать тип спеки,
но не должен выполнять init/use или импортировать runtime-модуль адаптера.
Чистая функция с ECharts-форматом не становится автоматически нейтральной любому движку.

canvas — исходный стандарт проекта; SVG выбирается осознанно по печати/экспорту/нагрузке.
Смена renderer требует пересоздания инстанса. Не меняй production renderer ради unit-теста.

| setOption | Когда |
| --- | --- |
| notMerge:false | Обычное обновление с сохранением интерактивного состояния |
| replaceMerge:['series'] | Удаление исчезнувших серий; используй устойчивые id |
| notMerge:true | Осознанный структурный сброс, с учётом легенды/зума/выделения |
| lazyUpdate:true | Отложенное применение частых обновлений, если подходит сценарию |

Без replaceMerge отсутствующие в новом наборе серии могут остаться после обычного merge.
Если option содержит legend, регистрируй LegendComponent даже при show:false. То же правило
для других используемых компонентов. Размер/геометрия проверяются до init и после resize.

## События и владение данными

`on(event, handler)` добавляет обработчик; cleanup использует `off(event, тотЖеHandler)`.
Эффект зависит от наблюдаемого инстанса/поколения, а callback читает текущий config.
`off(event)` снимает всех слушателей, допустим только при исключительном владении.

Добавляй исходную строку в точку: `{ value: row[valueField.id], name: row.categories,
dataContext: row }`. Обработчик читает params.data.dataContext; индексы после сортировки
не являются надёжной ссылкой на исходную строку. При сериях и цвете по полю сохраняй эту связь.

Один узел — один принадлежащий плагину инстанс. Повторный init существующего узла нельзя
считать универсальным способом создания второго экземпляра: поведение зависит от API версии.
Проверяй getInstanceByDom и владение, исправляй lifecycle; не вызывай dispose чужого экземпляра.

## Проверка

- Основные тесты — pure buildSpec и fake engine, включая удаление серий, сохранение состояния,
  данные клика и переподписку после смены инстанса.
- При ESM-ошибке Jest проверяй transformIgnorePatterns для echarts/zrender, условия exports
  и установленную версию; не правь бизнес-логику ради Unexpected token export.
- При необходимости добавь отдельный smoke-test реальной ECharts с SVG SSR или окружением,
  соответствующим версии. Он ловит незарегистрированные компоненты и некорректные options.
  Регистрация SVG в тесте не меняет production renderer; один мок этого не доказывает.
- На портале: реальная отрисовка, легенда после обновления, dataZoom, клики, resize, повторное
  открытие без накопления инстансов. Отчитайся отдельно о fake-engine и реальном прогоне.
