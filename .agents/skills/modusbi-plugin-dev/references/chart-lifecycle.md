# Жизненный цикл движка

buildSpec(config, plotData, theme) — чистое вычисление; владелец инстанса — эффект/компонент;
engine — адаптер вызовов create/render/resize/destroy. Подробности [раскладки](custom-chart-module.md).
Не выбирай библиотеку за пользователя: правила подходят ECharts, D3, Chart.js и своему canvas.

## Владение

| Фаза | Инвариант |
| --- | --- |
| create | Один инстанс на доступный DOM-узел ненулевого размера, когда статус ready |
| render | Обновление существующего инстанса новой спекой, без пересоздания на каждый render React |
| resize | Размер именно холста через ResizeObserver/useChartSize; resize окна не покрывает плитку |
| события | Одна подписка на поколение инстанса, точная отписка и актуальные callback |
| destroy | Размонтирование, смена узла/движка, выход из ready; очистка ссылок/подписок/таймеров |

Объект engine стабилен (константа/мемоизация). Инстанс хранится в ref или поле владельца;
его смена отдельно сигнализируется эффектам render/resize/events номером поколения либо
самим наблюдаемым значением инстанса. **Изменение ref.current не вызывает эффект**, если
зависимость — только стабильный объект ref. Это относится и к DOM-узлу: используй callback ref
с состоянием узла или другую явную идентичность при возможной замене контейнера.

Cleanup замыкает **конкретный созданный инстанс**, не читает потенциально уже заменённый
instanceRef.current для уничтожения. Сначала снимай принадлежащие ему подписки, затем destroy.
Не уничтожай найденный на DOM чужой инстанс без установленного владения. Каждый новый
инстанс получает текущую спеку, размер и обработчики, даже если данные не менялись.

При исчезновении данных освобождай инстанс, сохраняй контейнер. visibility:hidden сохраняет
размеры лучше display:none; статус определяет общая [оболочка](chart-shell.md).
Если инстанс сохраняется при временном нулевом размере, пропускай resize/render, требующие
геометрии, и восстанови их при положительном размере. Не допускай утечку в этом переходе.

Ядро может менять ссылки hsTheme/reportOptions/loadDatas/reloadDatas при одинаковом содержимом.
Для нестабильных callback используй актуальный ref; для значимых массивов/объектов — узкое
сравнение содержания или устойчивые примитивы. Не делай глубокое сравнение всего config на
каждый кадр и не убирай реальные зависимости ради подавления повторного вызова.

Классовый владелец допустим, если mount/update/unmount проще выражают владение; UNSAFE-методы
не нужны. Если геометрия спеки зависит от пикселей, обновляй размер и пересчитывай её согласованно.

## Интерактив

Преобразуй событие движка в доменную точку чистой toChartPoint, затем зови инжекты ядра.
Их сигнатуры не раскрыты полным образом в PluginInjectedProps: сверяй docs/api и целевое ядро.
Исходные наблюдения:

- drillDown(componentId, categoryFieldName, categoryValue) при drillDownActive.
- setCursorClicked/Hovered получают containerID, chartID, category {name, field}, value
  {amount, field}; при уходе hover — category:null, value:null.
- Если config.drill.hierarchy непустая, filterMode выключается для выбора кликового действия;
  иначе filterMode направляет к фильтрации, иначе возможен drill-down. Курсор выставляется
  во всех поддерживаемых ветках; Ctrl при фильтрации добавляет к выбору.
- changeFilterCategories и changeMultipleGlobalFilterValueAndApply обслуживают фильтрацию.
- dataCursorChanged на window нужен только при поддержке курсора соседних компонентов;
  снимай слушатель при cleanup.

Не придумывай недостающую сигнатуру или форму точки. Данные drill/cursor должны относиться
к исходной строке, а не к случайно совпавшему индексу после сортировки.

## Проверки

Fake engine проверяет порядок и количество create/render/resize/destroy, cleanup обработчиков,
смену DOM-узла при неизменной спеке, смену engine, ready→noData→ready, 0×0→положительный размер,
актуальность callback после ререндера. Pure buildSpec/toChartPoint проверяются без DOM.
На портале: изменение плитки, вкладок и повторное открытие отчёта; клики, фильтрация, drill;
сохранение выбранных серий/зума; отсутствие накопления canvas/svg и слушателей.
