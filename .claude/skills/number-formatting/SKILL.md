# Форматирование чисел

## Единая точка правды

**Число из данных превращается в строку для экрана ровно в одном модуле плагина.** Место —
`src/modules/CustomChart/model/format.ts` (папка `model/`, потому что функции знают про конфиг —
см. `custom-chart-module`); в шаблоне его нет, он заводится вместе с первым выводом числа.

Новое место вывода **обязано** звать функцию оттуда, а не писать свой `toFixed` /
`toLocaleString` / `Intl.NumberFormat`. Иначе точность, разделители и сокращения разъедутся
между подписью, подсказкой и новым местом при следующей правке одного из них — а заметит это
пользователь, а не тест.

Разделение по роду величины, а не по месту вывода. Обёртки не взаимозаменяемы:

| Функция                                           | Для чего                                           | Точность           | Суффикс единиц | Нет значения        |
| ------------------------------------------------- | -------------------------------------------------- | ------------------ | -------------- | ------------------- |
| `formatValue(value, precision, suffix, options?)` | агрегированное значение точки                      | `config.precision` | да             | `EMPTY_VALUE` (`—`) |
| `formatPercent(value, precision)`                 | доля со знаком `%`                                 | `precisionPercent` | нет            | `null`              |
| `formatPercentValue(value, precision)`            | доля **без** знака `%` — знак пишет шаблон подписи | `precisionPercent` | нет            | `null`              |
| `formatDelta(value, precision, suffix, options?)` | дельта со знаком (`+` / типографский минус `−`)    | `config.precision` | да             | `null`              |
| `formatExtra(extra, config)`                      | значение вспомогательной пилюли — по типу её поля  | `config.precision` | **нет**        | `EMPTY_VALUE`       |

Набор — образец, а не догма: плагину без процентов и дельт хватит первой строки. Что в нём
жёстко, так это **разница между `null` и `EMPTY_VALUE`**: `null` означает «показателя нет,
строки не будет вовсе», и вызывающий код обязан такой случай отфильтровать, а не печатать
`null`. `EMPTY_VALUE` (прочерк `—`) — наоборот, место занимается видимым прочерком.

Точку применения заводишь — вписывай её в таблицу «место → функция» в самом скилле или в
шапке `format.ts` тем же проходом. Таблица дешёвая, а без неё через три настройки никто не
скажет, все ли места пересчитались.

## Формат по правилам портала, а не по `Intl`

Разрядность и сокращения плагин **не считает сам** — он зовёт хелперы ядра (`formatNumber`,
`addPrefix` из констант форматирования ядра ModusBI), взяв их копией в свой репозиторий.
Разделители передаются явно и одинаково во всех вызовах: дробная часть — запятая, разряды —
**обычный пробел** (константами `DECIMAL_SEPARATOR` / `THOUSANDS_SEPARATOR` в `format.ts`).

Из этого два правила, которые не ломают без отдельного решения:

- **`Intl.NumberFormat` в плагине не используется.** Он ставит неразрывный пробел разряда,
  причём разный (U+00A0 либо U+202F) в зависимости от версии ICU, — сравнение строк в спеках
  становится зависимым от среды и падает на чужой машине. Хелперы портала ставят обычный
  пробел, и числа плагина выглядят как числа штатных диаграмм рядом на дашборде.
- **Ветку «числа меньше единицы» не переписывать.** `addPrefix` обрабатывает `|value| < 1`
  отдельно (`smallNumberClasses`, точность по `log10`) — плагин наследует это поведение вместе
  с хелпером намеренно, чтобы совпадать с остальной платформой.

**Копия кода ядра — не зеркало апстрима.** Она берётся как стартовая точка и правится, когда
того требует поведение плагина, — расхождение переносится вручную, автоматического мёржа нет.
Каждое сознательное расхождение помечается комментарием в самом файле, иначе следующий читатель
примет его за дословную копию. Два расхождения известны заранее и почти всегда нужны:

| Расхождение                                                                 | Зачем                                                                                              |
| --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `Math` берётся через guard по окружению (`window.Math` → `globalThis.Math`) | в ядре файл грузится только в браузере, а спеки идут в `testEnvironment: 'node'`, где `window` нет |
| Гашение «минус нуля» (`withoutNegativeZero`)                                | и буквальный `-0`, и `-0.4` при точности `0` дают пользователю одинокий минус перед нулём          |

Копия остаётся на JavaScript: конвертировать её в TS не нужно — тогда каждое обновление ядра
придётся переписывать заново. Место — `src/duplicates/` (в шаблоне папки нет, заводится вместе
с копией), под неё в `eslint.config.js` заводится блок ослабленных правил: код пришёл из ядра и
под линтер плагина не переписывался.

## Сокращения включаются набором, а не флагом

Сокращения больших чисел («1,2 тыс») задаются набором классов, который пользователь выбирает
готовой секцией ядра `suffixSelectContent`. Отдельного переключателя «сокращать» в панели нет и
заводить его не нужно: **сокращение включено ровно тогда, когда набор задан и непуст**, пустой
набор и его отсутствие означают полную запись.

```ts
export const abbreviationOptions = (config: Pick<ChartConfig, 'bigNumberClasses'>): FormatValueOptions => ({
  abbreviate: Boolean(config.bigNumberClasses?.length),
  bigNumberClasses: config.bigNumberClasses,
});
```

**Опции обязаны быть общими у всех мест вывода значения** — подписи точки, подсказки,
подзаголовка шапки. Разойдутся места — на одном экране окажутся «1,2 тыс» и «−150», величины
одного рода в разной записи. Поэтому опции берутся вызовом `abbreviationOptions(config)`, а не
собираются объектным литералом по месту: литерал в компоненте — это второй источник истины,
который расходится с первым молча.

Тип элемента набора (`{ number: number; prefix: string }`) объявляется рядом с `ChartConfig` в
`model/plugin.types.ts` — это форма поля конфига, здесь ей место. Справочник ядра со списком
конкретных классов в плагин не импортируется: классы существуют только как значения, которые
выбирает пользователь, а форматированию нужна форма, а не справочник.

## Откуда берутся настройки формата

| Настройка                | Поле конфига              | Кто пишет                                                                     |
| ------------------------ | ------------------------- | ----------------------------------------------------------------------------- |
| «Точность чисел»         | `config.precision`        | готовая секция ядра `sections.precisionSliderContent` — прямо в `configDraft` |
| «Суффиксы чисел»         | `config.bigNumberClasses` | готовая секция ядра `sections.suffixSelectContent` — прямо в `configDraft`    |
| «Точность процентов»     | `config.precisionPercent` | свой пункт панели → своя команда редьюсера                                    |
| «Формат даты»            | `config.dateFormat`       | свой пункт панели → своя команда редьюсера                                    |
| Суффикс единиц измерения | —                         | **не настройка**: читается из `field.units` пилюли значения                   |

Две первые секции подключаются в `Settings.tsx` как есть. **Записи в таблице `COMMANDS`
редьюсера для них нет и заводить не нужно** — ядро пишет значение в `configDraft` в обход
`changeChart` (установлено проверкой на портале). Свои две настройки живут по обычным пяти
точкам скилла `new-setting`.

`unitsSuffix` берётся из данных, а не из панели: читается `field.units` пилюли полки «Значения»
и отдаётся **с ведущим пробелом** (`' шт'`) либо пустой строкой — тогда `formatValue` клеит
суффикс без своего пробела. Отдельного текстового поля единиц измерения в панели заводить не
нужно, пока не появится явное требование.

`formatExtra` суффикс единиц **не приклеивает намеренно**: вспомогательная пилюля — другое поле
отчёта, и единицы основной пилюли к нему отношения не имеют. Форматирование решает тип поля:
`number` — точность `config.precision` правилами портала, `date` — шаблон `config.dateFormat`,
остальное — `String(value)` как есть. Нечисловое значение никогда не уходит в числовое
форматирование, иначе текст превратился бы в пустую строку.

## Старые отчёты

Три поля ведут себя по-разному, и разница не косметическая:

- **`precision`** — поле было в конфиге всегда, читается напрямую (`config.precision`). Значение
  слайдера ядра `-1` («авто») отдельным режимом реализовывать не обязательно, но точность перед
  `toFixed` **обязана клампиться к нулю**: нативный `toFixed` на отрицательной точности бросает
  `RangeError`. Самим хелперам портала отрицательная точность передаётся как есть — они её
  переживают штатно.
- **`bigNumberClasses`** — поле необязательное (`?`); в отчётах, где настройку не трогали, его
  нет. Пустой и отсутствующий набор трактуются одинаково. Дефолта в `defaultConfig.json` ему не
  нужно — поле пишет ядро.
- **Свои поля формата** (`precisionPercent`, `dateFormat` и подобные) в отчётах прошлых версий
  отсутствуют. Читать их **только** через `readConfigField` (скилл `new-setting`, шестая точка),
  не напрямую: там `??`, а не `||`, потому что `0` — валидная точность процентов. Дефолт один и
  берётся из `defaultConfig.json`.

## Порядок работы при правке

1. Правка `format.ts` — через `/tdd`: `test-writer` правит спек, `implementer` — функцию. Спек
   идёт в окружении `node`; ради этого в копии хелперов и стоит guard по окружению.
2. Правка формата задевает подписи, подсказку и шапку сразу — прогонять спеки сборки спеки
   целиком, а не только тот файл, который правился.
3. Новой команды редьюсера тема форматирования обычно не заводит: два ходовых контрола приходят
   готовыми секциями ядра. Понадобился собственный контрол — по скиллу `new-setting`.
4. Правился `defaultConfig.json` — обязателен прогон сабагента `settings-flow-reviewer`.
5. `npm test`, `npm run typecheck`, `npm run lint`.

## Частые ошибки

| Симптом                                                    | Причина                                                                          |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Подпись и подсказка показывают разное число                | второе место форматирует само, мимо `format.ts`                                  |
| «1,2 тыс» в подписи и «1200» в подсказке                   | опции сокращения собраны литералом по месту вместо `abbreviationOptions(config)` |
| Спек на формат зелёный локально и красный на другой машине | взят `Intl.NumberFormat` — неразрывный пробел зависит от версии ICU              |
| Разряды разделены не так, как у штатных диаграмм рядом     | разделители не переданы явно в хелперы портала                                   |
| При точности `0` показан «минус ноль»                      | потеряно гашение `-0` и значений, округляющихся к нулю                           |
| `RangeError` в `toFixed`                                   | точность `-1` («авто» слайдера ядра) не склампена к нулю                         |
| Текстовое значение вспомогательной пилюли стало пустым     | нечисловое поле ушло в числовое форматирование                                   |
| Единицы измерения прилипли к числу без пробела             | `field.units` отдан без ведущего пробела, а `formatValue` своего не ставит       |
| Настройка формата пропала в отчёте прошлой версии          | своё корневое поле прочитано напрямую, а не через `readConfigField`              |

## Смежные скиллы

- `new-setting` — пункт панели и команда редьюсера для своей настройки формата;
- `custom-chart-module` — почему `format.ts` живёт в `model/`, а не в `lib/`;
- `chart-shell` — подзаголовок шапки, ещё одно место вывода числа;
- `data-query-contract` — откуда в строке берутся `field.units` и тип поля.
