# Сверка контракта с ядром

`src/types/chartPlugin.d.ts` — снимок `prebuild/api/chartPlugin.d.ts` на момент копирования, сделанный руками. Ядро обновляется — снимок нет. Расхождение всплывает не на компиляции, а сломанной панелью редактора у пользователя.

## Порядок

### 1. Проверь, что источник истины на месте

```bash
cat prebuild/api/version.json
```

Нет каталога `prebuild/` — переносить нечего. Скажи об этом и остановись: контракт едет вместе со сборкой ядра, свежая версия лежит по адресу `<адрес портала>/api/chartPlugin.d.ts`, распаковывать её в `prebuild/` (каталог в `.gitignore`).

Сабагент `contract-reviewer` в той же ситуации не останавливается, а продолжает по снимку — ему есть что проверять и без источника (набор экспортов, методы осей, компиляцию). Если распаковать ядро сейчас нельзя, предложи пользователю этот путь как частичную замену.

Запомни `contractVersion` и `coreVersion` — их называешь в отчёте.

### 2. Сдиффь снимок с источником

```bash
diff -u src/types/chartPlugin.d.ts prebuild/api/chartPlugin.d.ts
```

Пустой diff — снимок актуален, переходи к шагу 5.

### 3. Разбери расхождения

Раздели вывод на три группы и покажи пользователю:

- **Контрактные** — изменились сигнатуры, появились или исчезли члены интерфейсов. Требуют переноса и, возможно, правок кода плагина.
- **Косметика** — комментарии, порядок, форматирование. Переносить стоит (снимок должен оставаться дословным), но кода это не касается.
- **Шапка снимка** — комментарий в начале `src/types/chartPlugin.d.ts` с `contractVersion`, `coreVersion`, датой копирования и запретом ручной правки. Её в источнике нет и быть не должно: это штатная часть снимка, а не расхождение. Не удаляй и не переспрашивай о ней — обнови в ней версии и дату на шаге 4.
- **Известный дефект комментария в самом источнике** (contractVersion 1.0.0): `VisibleAxeContext` подписан «Единственный метод осей, которому ядро не передаёт `componentType`», а `PillTypeOptionsContext` ниже — «Единственный контекст осей без `componentType`». Оба разом верными быть не могут: методов без `componentType` два. Структура типов при этом правильная. Переноси комментарии дословно, править их в снимке не нужно — но и верить им на слово тоже.
- **Прочие локальные вставки** — всё остальное, чего нет в источнике. Тело снимка дословное, поэтому такое находке равно: покажи отдельно и спроси, что с этим делать.

### 4. Перенеси изменения

Копируй в `src/types/chartPlugin.d.ts` дословно — снимок не «адаптируется» под плагин. Правь только снимок; `prebuild/api/chartPlugin.d.ts` не трогай, каталог перезаписывается при следующем обновлении ядра (на этот путь стоит блокирующий хук).

Сохрани шапку и обнови в ней `contractVersion`, `coreVersion` и дату копирования по `prebuild/api/version.json`.

Промежуточное состояние может не компилироваться — это нормально: снимок и код плагина приходят в согласие только к концу переноса. PostToolUse-хук для `*.d.ts` не блокирует, а возвращает ошибки как контекст, так что доводи перенос до конца и разбирай их на шаге 5.

### 5. Проверь последствия для кода

```bash
npm run typecheck
```

`src/index.ts` должен содержать тип `ContractCheck` — расхождение семи экспортов с `ChartPluginModule` роняет `tsc` здесь и только здесь.

Отдельно сверь `CustomAxesModule` с `src/modules/CustomAxes/index.tsx`: все методы контрактно необязательны, но отсутствующий метод возвращает `undefined`, что для большинства означает «пусто» — полка без имени, скрытая пилюля, пустая панель осей. Общее исключение — `getPillTypeOptions`: по контракту его отсутствие корректно означает «использовать штатный список ядра», и шаблон намеренно его не реализует. **Плагину, который сужает список типов пилюль своими значениями, метод нужно реализовать** — тогда его отсутствие становится такой же находкой, как отсутствие любого другого метода.

Появился в контракте новый метод осей — скажи об этом пользователю: скорее всего его нужно реализовать. Правила самого модуля (что означает «пусто» у каждого метода, какие методы не получают `componentType`, чем опасно тяжёлое тело `isVisibleAxeDragItemMenuOption`) — скилл `custom-axes-module`.

### 6. Обнови документацию

Если менялся `contractVersion` или `coreVersion`, поправь их упоминание в `CLAUDE.md` (раздел «Источник истины по контракту с ядром»).

## Отчёт

- версии `contractVersion` / `coreVersion` до и после;
- что перенесено в снимок;
- что это значит для кода плагина (сломанные экспорты, новые методы осей, изменённые сигнатуры);
- результат `npm run typecheck`.

## Помни

Контракт намеренно не раскрывает внутренние структуры — `config`, `field`, `axe`, `spec`, `data`, состояние редактора объявлены как `any`-псевдонимы, потому что в ядре они на нетипизированном JS. Их фактическую форму ищи по коду плагина и `src/modules/CustomChart/model/defaultConfig.json`, а не в контракте.

`docs/api` — более старый неформальный конспект. Полезен списками props и инжектов, которых в `.d.ts` нет. При расхождении верить `.d.ts`.
