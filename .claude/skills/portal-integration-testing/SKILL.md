# Проверка плагина в портале

## Суть

Юнит-тесты проверяют код плагина, портал — его **интеграцию**: реальный ответ бэкенда, реальный
CSS, реальную панель полок, реальное сохранение конфига. Ни одно из этого моками не
воспроизводится: мок `loadDatas` вернёт то, что в нём написали, а не то, что отдаст бэкенд.

Проверки делятся на два класса, и путать их не нужно:

- **Матрица интеграции** — постоянная, одинакова для любого плагина, вытекает из контракта ядра.
  Прогоняется целиком перед тем, как считать работу законченной.
- **Продуктовые проверки** — «что именно рисует этот плагин». Рождаются из требований по ходу
  разработки, заранее их не существует.

Скилл содержит первую целиком и задаёт форму для второй.

## Среда

### 1. Ядро берётся с того портала, где плагин будет жить

Скачивается со своего портала и распаковывается в `prebuild/`. Ключевое — **вместе с
настройками**: страница ядра несёт конфиг с адресом бэкенда, и без него локальный портал
поднимется, но данных не покажет.

Проверка занимает секунду и снимает половину будущих вопросов:

```bash
grep -c '#config#' prebuild/index.html
```

Ноль — конфиг подставлен, ядро знает свой бэкенд. Единица — в архиве остался незаполненный
плейсхолдер: ядро скачано не с портала или не тем способом, данных не будет. Скачивать заново,
чинить это правкой `prebuild/` бессмысленно — каталог перезаписывается при следующем обновлении
ядра, и правки в нём запрещены хуком.

### 2. Локальный запуск

```bash
npm start
```

Дальше `http://localhost:7000` (порт меняется переменной `PORT`). Устройство простое:
`webpack-dev-server` раздаёт `prebuild/` статикой, а `/plugins/custom_chart_0.js` отдаёт сам —
собранным на лету, с HMR. То есть **разрабатываемый плагин занимает нулевой слот**, подменяя
собой то, что лежит в `prebuild/plugins/custom_chart_0.js`.

Отсюда следствие, о которое спотыкаются: в отчёте-полигоне компонент должен быть **типа
`CustomChart0`**. Отчёт, где ваш плагин установлен в другой слот, локально покажет не его.

### 3. Вход

Логин и пароль вводит **пользователь сам**. Агент учётные данные не вводит, не запрашивает и
не хранит — ни в коде, ни в конфигах, ни в переписке. Если браузером управляет агент,
правильная последовательность: агент открывает страницу входа и **останавливается**, пользователь
входит, агент продолжает с уже авторизованной сессией.

Профиль браузера и сохранённое состояние сессии лежат в `.playwright-mcp/` — сессия переживает
перезапуски, повторно вводить пароль не нужно. Из репозитория исключены именно они
(`user-data/`, `output/`, `storage-state.json`, `secrets*` — см. `.gitignore`), а `config.json`
коммитится: секретов в нём нет.

## Отчёт-полигон

Нужен отчёт, на котором проверки повторяемы. Два пути, оба рабочие:

1. **Пользователь создаёт отчёт сам** и говорит агенту его адрес. Самый прямой путь, ничего
   ставить не нужно.
2. **Через MCP-сервер портала** (`mcp-modusbi`): отчёт, датасет и компонент создаются командами,
   полигон воспроизводится с нуля в любой момент.

Что в полигоне должно быть, чтобы он ловил типовые отказы:

| Что                                  | Что этим проверяется                                        |
| ------------------------------------ | ----------------------------------------------------------- |
| Датасет с текстовым и числовым полем | базовый путь: категории и значения                          |
| Две пилюли на полке «Значения»       | трейсы: ядро режет ответ по числу пилюль                    |
| Две пилюли на полке «Категории»      | ключи со скобками: `[categories][0]` вместо `categories`    |
| Заполненная полка «Фильтры»          | фильтры уходят отдельным аргументом, а не в составе запроса |
| Поле с пустыми значениями            | поведение на пустоте                                        |
| Датасет заведомо больше лимита строк | обрезка и её отображение                                    |

## Инструменты

Скилл рассчитан на работу **без каких-либо MCP-серверов**: тогда агент даёт пользователю
пошаговые указания, а тот выполняет их в браузере и присылает результат — скриншот, текст
ошибки, содержимое сетевой панели. Это медленнее, но полностью рабочий режим.

Два сервера ускоряют дело, и их стоит предложить установить, если задача упирается в ручной
цикл:

| Сервер         | Что даёт                                                                                                   |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| Playwright MCP | агент сам открывает портал, кликает, перетаскивает пилюли, снимает скриншоты, читает DOM и сетевые запросы |
| `mcp-modusbi`  | создание и настройка отчётов, датасетов и компонентов командами, без ручной сборки полигона                |

Предлагать — как рекомендацию, а не как условие: «эту проверку я могу сделать сам, если
поставить Playwright MCP; без него — вот шаги, выполните и пришлите скриншот».

## Матрица интеграции

Постоянная часть. Прогоняется целиком перед сдачей работы и после каждого изменения, которое
задевает контрактные экспорты.

### Появление и редактор

| Проверка                                                          | Признак отказа                                         |
| ----------------------------------------------------------------- | ------------------------------------------------------ |
| Плагин виден в палитре компонентов и добавляется в отчёт          | нет в списке — не подхватился бандл нулевого слота     |
| Компонент рисуется без ошибок в консоли                           | красное в консоли — почти всегда отсутствующий экспорт |
| Панель полок не пустая: названия, иконки, порядок                 | безымянные полки — не реализованы методы `CustomAxes`  |
| Пилюля перетаскивается на полку, недопустимое поле не принимается | принимается всё подряд — не работает `isDisabledAxe`   |
| Меню пилюли открывается, лишние пункты скрыты                     | чужие пункты — `isVisibleAxeDragItemMenuOption`        |

### Данные

| Проверка                                                           | Признак отказа                                       |
| ------------------------------------------------------------------ | ---------------------------------------------------- |
| Запрос ушёл: в сетевой панели виден запрос данных с непустым телом | пустое тело — `getQueryObjects` вернул пустой массив |
| Число объектов запроса равно числу пилюль полки «Значения»         | один объект на всё — трейсы не собраны               |
| Ответ разобран: строки построились, число строк ожидаемое          | ноль строк — `remapData` не нашёл ключи              |
| Многопилюльная полка «Категории» читается                          | `undefined` — ключ приходит как `[categories][0]`    |
| Фильтр компонента влияет на выборку                                | не влияет — значения фильтров не доехали до запроса  |
| Смена пилюль перезапрашивает данные                                | старые данные — не сработала зависимость эффекта     |

### Настройки и конфиг

| Проверка                                                          | Признак отказа                                                        |
| ----------------------------------------------------------------- | --------------------------------------------------------------------- |
| Панель настроек открывается, все секции на месте                  | пустая панель — `CustomSettings` вернул `null`                        |
| Изменение настройки видно на компоненте сразу                     | не видно — забыт `autoApplySettings`                                  |
| Режим ручного применения: правка ждёт кнопки и применяется по ней | применяется сразу — редьюсер обошёл `autoApplySettings`               |
| Сохранить отчёт, закрыть, открыть — настройки и полки на месте    | сброс — конфиг не дошёл из `configDraft`                              |
| Отчёт, сохранённый прошлой версией плагина, открывается           | падение — несовместимость: новые поля читаются без запасного значения |

### Вид и поведение

| Проверка                                                             | Признак отказа                                       |
| -------------------------------------------------------------------- | ---------------------------------------------------- |
| Шапка на месте, длинный заголовок обрезается                         | своя вёрстка вместо классов ядра — см. `chart-shell` |
| Кнопки ядра в правом верхнем углу нажимаются                         | перекрыты — нет правого отступа шапки                |
| Кнопка «Информация» переворачивает компонент к описанию              | пустой оборот — не реализован `backSide`             |
| Перетаскивание границы плитки перерисовывает диаграмму               | обрезка — размер снимается не с контейнера           |
| Переключение вкладок отчёта и возврат не задваивает холст            | два холста — инстанс не уничтожается                 |
| Клик по точке: детализация или фильтрация в зависимости от настройки | нет реакции — см. `chart-lifecycle`                  |

### Дистрибутив

| Проверка                                            | Признак отказа                                  |
| --------------------------------------------------- | ----------------------------------------------- |
| Архив собирается и ставится на портал               | см. `package-plugin`                            |
| Установленный плагин работает так же, как локальный | расходится — в слоте не подставилось имя класса |

## Продуктовые проверки

Матрица выше не знает, что рисует ваш плагин. Эта часть растёт из требований — по одному
проходу цикла `tdd`.

Требование к этому моменту уже записано пятью полями (форма — в CLAUDE.md, раздел «Требования
не выдумываются»): вход, ожидаемое поведение, пустые данные, ошибка запроса, сохранённый
прошлой версией конфиг. Три последних поля почти целиком уходят сюда: пустую выборку моком
подделать можно, а вот отказ реального бэкенда и старый отчёт с новым кодом проверяются
только в портале.

Правило простое: **сформулированное требование раскладывается надвое**.

| Куда                        | Что туда идёт                                                           |
| --------------------------- | ----------------------------------------------------------------------- |
| Юнит-тест                   | всё, что проверяется без портала: спека, форма запроса, разбор ответа   |
| Строка портального чеклиста | всё, что моки не воспроизводят: реальный ответ, CSS, панель, сохранение |

Форма строки — три поля, иначе через неделю её не воспроизвести:

```
Что делаем:   на полку «Значения» кладём две пилюли, на «Категории» — одну
Что ожидаем:  два ряда столбцов, подписи категорий по оси X, легенда из двух имён
Признак сбоя: один ряд — значит трейсы слиты в одну строку
```

Чеклист живёт рядом с плагином (например, `docs/portal-checklist.md`), а не в переписке:
проверяется он каждый раз перед сдачей, а помнить его наизусть никто не будет.

## Что автоматизируется, а что нет

| Автоматизируется хорошо                          | Делается глазами                    |
| ------------------------------------------------ | ----------------------------------- |
| Наличие компонента, узлов, классов, текста в DOM | «диаграмма выглядит правильно»      |
| Тело и параметры сетевого запроса                | цветовая гамма, читаемость подписей |
| Ошибки в консоли                                 | плавность анимации                  |
| Сохранение и восстановление конфига              | общая соразмерность в плитке        |

Скриншот-дифф на диаграммах даёт ложные срабатывания из-за антиалиасинга и анимаций — как
обязательную проверку его заводить не стоит. Скриншот полезен как **свидетельство**: приложить
к отчёту, чтобы человек посмотрел один раз.

Артефакты браузера (скриншоты, трассировки) складываются в `.playwright-mcp/output/` — каталог
исключён из репозитория.

## Границы

- **Учётные данные вводит только пользователь.** Агент не вводит и не хранит логины, пароли и
  токены.
- **Боевой портал не трогать.** Проверки идут на тестовом; установка плагина, правка чужих
  отчётов и датасетов на боевом контуре — не работа агента.
- **Чужие отчёты не менять.** Полигон — свой отчёт; если его нет, попросить создать или создать
  через MCP-сервер, а не переиспользовать чей-то.
- **Результат не приукрашивать.** Не прогнал проверку — так и сказать; отчёт «всё работает» без
  прогона матрицы бесполезен и опасен.

## Отчёт

По итогам называть: какие пункты матрицы пройдены, какие провалены и с каким признаком, какие
не проверялись и почему (нет доступа, нет полигона, нет MCP), и что из продуктового чеклиста
добавилось за этот проход.
