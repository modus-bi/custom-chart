# TypeScript и инструментарий

Применять к коду и спекам плагина. Конфиги CommonJS остаются JS; дословный снимок контракта
не перерабатывать под эти конвенции. Версии/опции сверять по целевому проекту.

- Используй `import type`/`export type` для типовых связей: SWC транспилирует файлы отдельно,
  `isolatedModules` выявляет несовместимые конструкции. Это явное отделение runtime-кода,
  а не утверждение, что любой обычный type-only import обязательно сохранится в каждом SWC.
- При classic JSX импортируй React в TSX-файлах с JSX. Не переключай runtime автоматически:
  `react/jsx-runtime` не входит в пару externals шаблона.
- Новые данные на непроверенной границе принимай как `unknown`, проверяй форму перед чтением.
  Утверждение `as ChartConfig` само ничего не валидирует. Допустимы локальные assertions для
  уже доказанной формы; ими нельзя заменять исследование отсутствующего API или гасить ошибки.
- `interface` — формы объектов и классовый контракт; `type` — union, mapped/intersection,
  функциональные и вспомогательные типы. `?` и `| null` отражают разные состояния.
- Формы config/plotData — `CustomChart/model/plugin.types.ts`; props одного компонента —
  рядом с компонентом; общие props настроек/ChangeChart — `CustomSettings/types.ts`.
- camelCase для функций/переменных, PascalCase для типов/компонентов без I/T-префикса,
  UPPER_SNAKE_CASE для констант и команд. Неиспользуемые контрактные параметры — `_config`.
- Экспортируемым функциям давай явный тип результата там, где это помогает удержать контракт.
  Не сокращай обязательную сигнатуру ядра ради правила «до трёх аргументов».
- Компоненты и чистые хелперы обычно функциональные. Классы нужны контрактным конструкторам;
  error boundary в React 16 и владелец движка с явным lifecycle также допустимы.
- Импорты: внешние → типы → внутренние значения → стили, группы через пустую строку.
  В шаблоне относительные пути, SCSS без CSS modules; в чужом проекте сохраняй его конфигурацию.
- displayName у компонентов панели/визуализации; интерфейс и полезные комментарии — по-русски.
  Комментарий объясняет действующий контракт, не пересказывает историю разработки.

## Зависимости и копирование данных

UI ядра передаётся через `pluginImports.components/sections/services`. Не импортируй UI-kit.
Вся новая runtime-зависимость вне externals увеличивает бандл: сохраняй выбранный пользователем
движок; не ставь пакет для тривиального `join` или присваивания по пути.
Для HTML-описания применяй существующий проверенный санитайзер либо DOMPurify по
[оболочке](chart-shell.md); это целевой инструмент, а не разрешение на любую зависимость.

Не добавляй `react-addons-update`. Для данных конфига подходит `structuredClone`, для
неглубокого состояния — spread. Функции и DOM/React-узлы не клонируются structuredClone,
прототипы пользовательских классов не сохраняются. Не заменяй механически работающий
алгоритм клонирования там, где в структуре есть такие значения.

## Проверки

Форматирование определяет конфиг Prettier проекта: не форматируй весь репозиторий заодно.
Используй установленный локальный бинарник через npm exec/npx с запретом скачивания либо
проектный script. Typecheck **запускай явно** после законченного изменения: хуков здесь нет.
`npm run lint` проверяет ESLint, не заменяет компилятор.

`types: ["jest"]` в tsconfig включает globals тестов и ограничивает автоматическое подключение
других globals. При TS2593 проверяй эту опцию, не отключай типизацию спеков. jsdom может не
предоставлять `structuredClone` и `ResizeObserver`: используй подходящее окружение или
точечные моки. JSON stringify/parse — только копия JSON-фикстур, не полноценный полифилл.
