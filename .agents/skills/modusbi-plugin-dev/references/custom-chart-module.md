# Раскладка CustomChart

Для нового кода шаблона папку определяет роль файла. При узкой правке другого плагина
не переносить весь модуль; миграция типов и перестройка папок — отдельные изменения.

```text
src/modules/CustomChart/
  index.ts              публичная граница модуля
  CustomChart.tsx        главный компонент
  dataAdaptor.ts        контрактный конструктор
  specGenerator.ts      контрактный конструктор
  configEditor.ts       контрактный конструктор
  model/                config, типы данных, buildSpec, toChartPoint, format
  ui/                   шапка, оборот, статусы, error boundary
  hooks/                useChartSize, владение инстансом, события
  lib/                  чистые функции без знания конфига, React и DOM
  engine/               адаптер выбранного движка и его типы
```

- `model/` знает полки/пилюли/конфиг, но не владеет DOM. `lib/` работает с независимыми
  примитивами: например `getLocal`; форматирование, читающее ChartConfig, относится к model.
- `engine/` создаётся вместе с движком. Runtime-импорты библиотеки и преобразование вызовов
  движка сосредоточь здесь; хуки управляют временем жизни. `buildSpec` может получать тип
  спеки через `import type` из `engine.types.ts`, оставаясь чистой функцией без init/use/DOM.
  Это изоляция runtime и побочных эффектов, не обещание, что формат ECharts нейтрален движку.
- Не заводи параллельную `utils/`, и barrel `index.ts` в каждой подпапке.
- Снаружи импортируй публичную границу модуля; внутри — прямые относительные файлы.
  `ComponentTypeManager` зависит от экспортов CustomChart и сам используется компонентом:
  прямые импорты контрактных файлов нужны для разрыва цикла, поясни это комментарием.
- Реэкспортируй контракт, типы конфигурации и реально публичные функции, не весь ui/lib.
- Спеки лежат рядом с файлом и перемещаются вместе с ним. Хелпер для одного потребителя
  обычно остаётся рядом; самостоятельная проверяемая чистая функция оправдывает ранний вынос.
- Разросшийся метод CustomAxes выноси по его роли: знание полок → model, универсальность → lib.

Проверяй новые импорты на циклы и сохранность семи экспортов. Наличие props в файле компонента
нормально; общие формы данных держи отдельно. Не создавай пустые каталоги на будущее.
